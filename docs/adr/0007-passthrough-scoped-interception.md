# A Scope also narrows what is decrypted, under a second concept called Passthrough

`start_capture` gains `passthrough: bool = True`. When it is on and a `scope` is named, mitmproxy is told to decrypt only those hosts; every other TLS connection is forwarded without being opened, so it reaches its destination carrying the real certificate. With no `scope` the parameter does nothing, because there is nothing to distinguish. `capture/hostsets.py` owns what a host entry means and renders the engine's patterns from the same definition the Scope predicate answers from.

The defect this fixes was reported from real use. Redirecting the system proxy redirects the whole Mac, and the Interception Authority is installed into exactly one simulator — so while a Session recorded, the developer's browser showed a certificate warning naming `mitmproxy` as the issuer for sites they had never asked about, and every *other* booted simulator lost network access. Nothing warned them, and nothing told them it was happening. A probe established the fix and the evidence for it in one step: with `allow_hosts` set, `openssl s_client -proxy` saw `/CN=mitmproxy` for the named host and Google Trust Services for the unnamed one, with no Authority installed anywhere.

## Considered options

- **Redefine Scope to mean both, with no second parameter.** One concept is simpler, and it was rejected because `capture/reporting.py` exists to distinguish what gets *reported* from what was captured. Folding interception into that word makes the distinction unstateable, and the sentence "capture is unconditional" — which P3 and P4 both reason from — stays true for the default. Passthrough is therefore a second term in `CONTEXT.md` and Scope keeps its meaning, gaining one clause.
- **A second host list for interception.** Rejected as a maintenance trap: an agent should not have to keep two nearly-identical lists in step, and in practice they would always be the same. Passthrough takes the Scope's hosts as its input and has no host list of its own.
- **Default it off.** A default that changes what gets captured looks reckless. The alternative default silently breaks the developer's browser and every other simulator on the machine, and the parameter is inert until an agent has said which hosts it cares about, so the risk is bounded by the agent's own statement of intent. `passthrough=False` remains available for the case below.
- **Let the builtin denylist feed Passthrough too.** It would spare OS chatter on an *unscoped* Session, which is where the collateral damage is worst, and it was rejected on the strength of what the denylist is. It is a reporting narrowing whose entries stay fetchable by id on purpose, and `reporting.py` records that its **omissions** are the delicate part: `googleapis.com` is deliberately absent because for many apps it is the backend. A wrong entry in a reporting narrowing costs a hidden row; a wrong entry in a transport decision costs traffic that was never captured and cannot be recovered.
- **Observe or count what was passed through, so the diagnosis could measure rather than deduce.** mitmproxy has the option — `show_ignored_hosts` — and its own help warns that it will keep every ignored connection's contents in memory, "which can greatly increase memory usage". On a machine-wide proxy that is the entire machine's traffic buffered inside this server, which is the one thing Passthrough exists to stop this tool doing. It stays off and `diagnose_capture` says only what it can honestly infer from "Passthrough is on and this host is not in the Scope".
- **Install the Interception Authority on the Mac itself instead.** It would silence the browser warning and would help no other simulator, while leaving a machine-wide interception authority trusted for as long as it stayed installed. `install_authority_system` continues to exist as an explicit, separate action for someone who has decided to capture their own browser; it is not how this defect is fixed.
- **A new module for host-set semantics, rather than a sibling of `in_scope`.** Two independent expressions of one host-set rule is the trap `targets/CLAUDE.md` records as costing a real debugging session — a reader that normalises can hide a writer that does not — and here it would surface as a Scope that reports a host's traffic while never decrypting it. `in_scope` became a thin delegate so both existing call sites were untouched.

## Consequences

**The accepted regression.** `wait_for_exchanges` and `get_exchange` are deliberately exempt from the Scope, on the grounds that an explicit question should not be vetoed. Under Passthrough they find nothing for an HTTPS host outside the Scope, because that traffic was never decrypted — so a wait blocks to its timeout instead of being vetoed. This is knowingly accepted: it is recoverable by restarting with a wider Scope or `passthrough=False`, where the old default was recoverable only by already knowing about it. It is also why `diagnose_capture` appends a sentence saying so to the two verdicts an agent reaches when a listing is empty.

**Passthrough covers TLS only.** Measured by hand after the work was written, and it contradicted the design's own prose. mitmproxy's `_ignore_connection` answers "do not ignore" when it has no host name to test, and a plain-HTTP proxy request does not name its destination until the request line is parsed — after the layer has been chosen. Only a `CONNECT` authority and a TLS SNI arrive early enough. So plain HTTP is intercepted whatever the Scope says: in the hand-verification every recorded Exchange was plain-HTTP bundler traffic from a host the Scope never named. Harmless for the reported symptom, since plain HTTP has no certificate to reject, and arguably useful. But the two cases have opposite remedies — an out-of-scope HTTPS row needs a new Session, an out-of-scope plain-HTTP row needs an id — so both are stated wherever either is.

**Passthrough shrinks the certificate blast radius, not the availability one.** Out-of-scope connections are still *forwarded by* this process, so the machine's traffic still stops if it dies. That is what ADR-0008 addresses, which is why the two landed together.

`SPEC.md` says capture is unconditional and its `start_capture` row has no `passthrough`. Both are now untrue of the code and both stay: it is a record of intent. The divergence is recorded in `.claude/agents/doc-drift-reviewer.md`, without which every future documentation review reports it as a fresh finding.
